## Recommendation

**Option 1: Global Enable + Suppress**

- Set `<Nullable>enable</Nullable>` in Sage4.csproj (one change)
- Add `#nullable disable` to all 548 source files initially
- Remove pragma as files are annotated in phases
- Clear migration tracking: `grep -r "#nullable disable" Sage/ | wc -l`
- Aligns with Microsoft guidance and ASP.NET Core's own strategy

## Phased Migration Plan

**Phase 1 — Core Contracts (Highest Priority)**
- Annotate public interfaces: IExecutive, IModel, IExecEvent, IModelObject, etc.
- Estimated effort: 1–2 hours
- Risk: LOW for interfaces; MEDIUM for `object? userData` propagation (public API surface change)

**Phase 2 — Engine Internals**
- Executive.cs, ExecutiveFastLight.cs, Model.cs, InitializationManager.cs, etc.
- Estimated effort: 4–6 hours
- Risk: MEDIUM-HIGH (complex constructor patterns)

**Phase 3 — Remaining Modules**
- Batch by namespace, assign to Parker in priority order
- Highest-effort: Graphs (1,160 warnings), Persistence (special handling)

**Phase 4 — Cleanup**
- Remove remaining pragmas (except permanent exclusions)
- Enable warning-as-error for key nullable rules
- Final validation

## Architectural Constraints (Non-Negotiable)

1. **`object userData`** — Annotate as `object?` where callers pass null. Do NOT change to generic `T`.
2. **`IDictionary graphContext`** — Keep non-generic. Annotate `?` only where null is actually passed.
3. **`WeakHashTable`** — Permanent `#nullable disable`.
4. **Persistence files** — Default to permanent `#nullable disable` unless specifically clean.
5. **Public API changes** — Every return type change `T` → `T?` on public interface must be listed in PR as "Breaking Changes" (source-compatible).
6. **`= null!`** — Use sparingly, only for fields guaranteed initialized before use. Never on fields that might actually be null.
