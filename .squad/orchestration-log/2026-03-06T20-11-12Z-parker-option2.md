## Root Cause Discovery

While testing Option 2, Parker discovered the **actual root cause** in `Exchange.NonBlockingPost()`:

### The Bug (Exchange.cs lines 159-164)

```csharp
foreach (IDetachableEventController idec in _waitersToRead[tuple.Key])
    idec.Resume(_readPriority);
foreach (IDetachableEventController idec in _waitersToTake[tuple.Key])
    idec.Resume(_takePriority);
_waitersToRead.Remove(tuple.Key);
_waitersToTake.Remove(tuple.Key);
```

**Issue:** Generic `HashtableOfLists<TKey,TValue>` indexer throws `KeyNotFoundException` if key doesn't exist (differs from non-generic version which returns empty list).

### Why .NET 10 Exposed It

.NET 10's different thread pool startup timing and scheduling altered execution order, hitting this race condition more frequently. Bug existed on .NET 8 but was timing-masked.

## The Actual Fix

Added `ContainsKey()` checks in `Exchange.NonBlockingPost()`:

```csharp
if (_waitersToRead.ContainsKey(tuple.Key))
{
    foreach (IDetachableEventController idec in _waitersToRead[tuple.Key])
        idec.Resume(_readPriority);
    _waitersToRead.Remove(tuple.Key);
}
if (_waitersToTake.ContainsKey(tuple.Key))
{
    foreach (IDetachableEventController idec in _waitersToTake[tuple.Key])
        idec.Resume(_takePriority);
    _waitersToTake.Remove(tuple.Key);
}
```
