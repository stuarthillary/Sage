## Key Findings

### Executive vs EFL Behavior Divergence

| Aspect | Executive | ExecutiveFastLight |
|--------|-----------|-------------------|
| **IgnoreCausalityViolations=true (default)** | Returns `long.MinValue`; event **dropped** | Clamps to `_now`; event **fires at _now** |
| **IgnoreCausalityViolations=false (enforce)** | Throws `CausalityException` → `RuntimeException` | Logs to Console.WriteLine; **throw is commented out**; event still fires |

### Root Cause: Design Intent vs Code Quality

1. **Intentional divergence:** Executive prioritizes strict DES correctness; EFL prioritizes throughput.
2. **Code smell:** EFL's throw statement is commented out — "enforce mode" doesn't actually enforce.
3. **Behavioral risk:** Users configuring EFL with `IgnoreCausalityViolations=false` expecting exceptions will get silent logging instead.

---

## Recommendations

1. **Document the divergence** in XML docs on `IExecutive.RequestEvent()`
2. **Fix EFL's commented-out throw** — either implement enforcement or document the log-only mode
3. **Maintain divergence** — do not unify without RFC (breaking change for users)
4. **Use existing test isolation pattern** via `ExecFactory.Configure()` + `ResetExecFactorySingleton()`
