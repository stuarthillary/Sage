## Key Learnings

1. **Interface-first vs. concrete-first design:** Separating interface changes from concrete implementation changes isolates risk classes. `p3-interfaces` proved the interface contracts work; `p3-edge-vertex` aligns concrete implementation.

2. **Scope boundaries prevent drift:** Explicitly preserving storage, serialization, and parent plumbing in Batch 2 prevented scope creep into orthogonal subsystems (persistence, graph parent tracking).

3. **Rejection → revision cycle strengthened design:** Hudson's rejection forced explicit scope definition and sign-off, clarifying what "Batch 2 concrete alignment" actually means (not a full rewrite, just public surface + immediate fallout).

4. **Regression test seams matter:** Concrete API regression tests (`TestGraphBranching.cs`) proved valuable for detecting incomplete implementations before wider system testing.
